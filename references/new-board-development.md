# Mode 4 — 新板卡环境初始化

## 目标

为尚未建立协作环境的板卡初始化可复用的硬件事实和协作入口。它不创建 Vivado
工程，也不进行功能开发。

初始化的共享内容为：

```text
AI-work/
  README.md
  LOG.md
  HARDWARE_ENVIRONMENT.md
```

`README.md`、`LOG.md` 和 `HARDWARE_ENVIRONMENT.md` 均服务后续所有模式。`LOG.md`
简洁记录本次环境初始化的计划、实际审阅资料和验收结论。其他目录按实际记录需求创建，
不使用空目录占位。

## HARDWARE_ENVIRONMENT.md

记录深度与可得资料相称，但任何用于实际 XDC、时钟、IP 参数或板级动作的事实都必须
有明确来源。

至少记录：

1. 板卡/装配版本、FPGA 型号/封装/速度等级、工具版本、JTAG/配置接口、Git 地址和
   资料来源；
2. 已知普通 IO Bank 的电源网、确认电压和专用配置/时钟/GT 资源；电源网名不等于
   电压值；
3. 每张已审阅 FPGA 页的每个非电源 FPGA ball、时钟脚、配置脚、GT lane 和参考时钟的
   单行映射；未审阅页明确标为未覆盖；
4. 已追踪接口的 FPGA 至外设端到端路径，或路径尚未闭合的位置；
5. 待确认事实、对功能的影响、最小下一证据和结论更正记录。

每条映射标注证据状态，例如“视觉确认”“文本提取，待视觉核对”或“用户确认”。同页
文字共现、相似网络名、旧 XDC 和相似板卡均不是连接或电气参数证据。

环境可为 `PARTIAL`。未使用接口或未闭合的跨板路径不阻塞已经具备全部所需事实的功能
工作包；需求实际涉及的接口则不得缺少管脚、电压、极性、时钟或端到端连线证据。

## 交给 Mode 3

用户提出功能需求后，在 `AI-work/work-packages/<需求名>-<日期>/` 创建工作包，仅
提取该需求相关硬件事实。用户尚未创建或指定 `.xpr` 时，将其列为前置条件；AI 不通过
Tcl 创建替代空工程。
