# Mode 4 — 新板卡工程初始化与硬件环境

## 目标与边界

Mode 4 在新板卡开发开始时建立可复用的工程协作骨架和硬件环境。它的交付物是准确、可追溯的原理图到 FPGA 资源映射，使后续需求能够安全地编写 XDC、选择 IP 和设计板级操作。

Mode 4 不是全板 bring-up：不得自动创建接口 Demo、产品基线、Release、交接包或空的 Vivado 工程。不得以“将来可能需要”为由预先实现 DDR、ADC、Flash、GT 或网络接口。

在本模式中不得创建 `fpga/`、RTL、XDC、IP 或 Vivado `.xpr`。只有某个功能需求经用户确认后，才在该需求的工作包中以 Tcl 创建实际 Vivado 工程。

## 初始化文件

在项目根目录创建且仅创建下列基础记录：

```text
AI-work/
  README.md
  LOG.md
  HARDWARE_ENVIRONMENT.md
```

`README.md` 说明本目录的用途、工作包路径和提交规则。`LOG.md` 是按时间追加的简要索引，记录环境建立和每个工作包的计划、执行、验收结论。`HARDWARE_ENVIRONMENT.md` 是唯一的全局硬件事实来源。

不要创建 `fpga/` 子目录、空的 Vivado 工程或占位源文件。后续经批准的第一个功能需求若需要工程，应在 `fpga/` 中保留其 Tcl、源码、约束和 Vivado 产生的工程内容；工程的准确布局由该需求方案决定。

## HARDWARE_ENVIRONMENT.md

该文件必须包含：

- 项目路径、Git 远程地址、板卡名称/版本、FPGA 型号/封装/速度等级、目标工具和版本；
- JTAG/配置接口的原理图事实，以及经授权的被动观测结果；
- 每份输入原理图、数据手册或用户确认的路径、版本、适用范围和页码；
- 原理图中所有连接到 FPGA 的信号与 FPGA 管脚/GT/专用资源的一一对应关系；
- 时钟、复位、配置、JTAG、Bank 电压、差分对、GT 参考时钟和外设控制等硬件事实；
- 每项事实的来源和状态：`已确认`、`待确认` 或 `推断`。

管脚映射至少应使用下表字段：

| FPGA 管脚、Bank 或专用站点 | 原理图网络 | 连接器/器件/功能 | 方向与电气属性 | 来源页码 | 状态 |
|---|---|---|---|---|---|

只要原理图资料能够给出某个 FPGA 信号，就应写入该映射；对资料缺失、版本不明或无法闭合的信号明确写 `待确认`，不得根据网络名伪造 XDC 或 IP 参数。此文件可由后续需求追加、更正，但每次更新必须保留来源和变更记录。

## 后续需求工作包

用户提出功能需求后，创建一个工作包：

```text
AI-work/work-packages/<需求名>-<日期>/
  PLAN.md
  EXECUTION.md
  ACCEPTANCE.md
```

不要为尚未提出或尚未确认的需求预建工作包。

1. **计划**：从 `HARDWARE_ENVIRONMENT.md` 提取相关接口事实；缺失时只追踪该需求相关的资料并同步回总环境文件。记录目标、范围、待修改文件、Tcl/Vivado 工程策略、默认安全行为、验证、板级操作、停止条件和验收标准。
2. **确认**：等待用户确认计划。若用户已明确授权计划中的开发和板级操作，可记录该授权。
3. **执行**：只实施批准范围。若需要 Vivado 工程，编写并运行受版本控制的 Tcl；不得通过空工程或 GUI 手工步骤替代可复现的创建过程。关键硬件事实与计划不符时，停在安全边界并重新提交方案。
4. **验收**：在 `ACCEPTANCE.md` 以预先定义的标准报告仿真、构建、时序、镜像、板级观测和未解决限制。构建成功不等于板级或协议通过。
5. **提交**：用户接受验收结论后再提交或推送，除非用户明确预授权自动提交。

LED 工作包只需引用 LED 管脚、Bank 电压、有效电平和所用时钟。Flash 工作包额外追踪 Flash 型号、SPI 管脚/模式、写保护和原镜像保护策略。SGMII/UDP 工作包额外追踪 TX/RX lane、极性、GT 参考时钟、PHY 模式/MDIO/复位以及网络/协议参数。无关接口不应阻塞当前工作包。

## 板级操作和验收

下载 bitstream、擦写 Flash、写 PHY/MDIO、复位外设或发送主动网络报文，必须在已确认的 `PLAN.md` 中逐项声明目标、候选镜像或命令、最小观测、停止条件和恢复方式。被动 JTAG 枚举也应记录为一次已授权的观测。

Mode 4 本身完成时，应在 `LOG.md` 记录计划、执行和验收：基础文件已创建、硬件环境的资料覆盖范围、待确认项，以及确认没有产生 FPGA 工程或板级状态改变。用户接受后才提交或推送该初始化结果。

## 旧全量工作包

`assets/new-board-work-package/`、`validate-new-board-work-package.py` 和相关全量 bring-up 资产仅保留给已有项目的兼容维护；新的 Mode 4 不创建、不调用也不要求它们。
