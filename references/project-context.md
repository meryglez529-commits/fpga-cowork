# 工程上下文

首次确认用户指定的 Vivado GUI 工程后，建立或补齐工程上下文，记录工程定位、工作入口
和已有设计方案入口。沿用已有承担此职责的文件；新建时默认使用 `AI-work/CONTEXT.md`，
同一协作范围维护一份即可。

内容以路径和链接为主，按工程实际情况记录：

| 内容 | 记录范围 |
|---|---|
| 工程身份 | `.xpr` 路径；存在多个工程时说明各自角色及共用关系 |
| 工作入口 | 源码、约束、IP、脚本、日志和原生产物的位置；能由工程根目录确定的常规路径无需逐项展开 |
| 设计方案入口 | 已有且已确认的总体方案、模块方案的路径或链接，有则记录 |

继续工作时按任务读取上下文和相关方案。缺少入口时补充，工程角色、路径或方案入口
变化时更新；不在此维护逐轮进度和执行经过。实际 top、fileset、run 状态、镜像有效性
等信息在执行对应流程时从工程和原始证据核对。

## 设计方案

总体方案、模块方案是设计阶段的交付物，沿用任务确定的名称和位置，直接维护其中
当前有效的设计及必要理由。设计改变时修订受影响内容，保持方案与实现一致。
工程上下文只提供入口，详细内容由对应方案承载。

## 执行结果与其他资料

日志和原生产物按对应流程保存，普通执行在回复中说明结果和证据入口，无需额外建立
记录文档。可复用的操作按需保留脚本及必要说明；需要长期使用的结论优先修订已有相关
文档，无合适归属且有独立使用需要时单独保存，名称和位置按任务决定。同一结论只维护
一份，其他文档引用其入口。
